# Trackside — IoT Gateway Telemetry Sync Contract

This specification defines the hardware-to-backend communication protocol for physical IoT gateways (ESP32 kart units, smart gloves, and telemetry hubs).

## 1. Authentication

Physical hardware authenticates using **Device Token Authentication**:
- **Header format**: `Authorization: Device-Token <token>` or `X-Device-Token: <token>`
- Token is a 32-character random string generated by the Admin during device registration.
- Backend verifies the SHA-256 hash of the token in constant time.
- Updating `last_seen_at` and marking device status as `CONNECTED` occurs automatically on every valid request.

## 2. Telemetry Ingestion API Endpoint

- **Endpoint**: `POST /api/sessions/<session_uuid>/telemetry/`
- **Content-Type**: `application/json`

### Payload Formats

#### Single Reading Payload
```json
{
  "recorded_at": "2026-08-12T10:15:30.120Z",
  "lateral_g": 1.14,
  "speed_kmh": 87.5,
  "gps_lat": 11.016842,
  "gps_lng": 76.955831
}
```

#### Bulk Batch Ingestion Payload (Buffered Network Recovery)
When connectivity drops, gateways buffer readings locally (e.g. SQLite / SPIFFS flash) and POST a batch upon reconnection:
```json
[
  {
    "recorded_at": "2026-08-12T10:15:30.120Z",
    "lateral_g": 1.14,
    "speed_kmh": 87.5,
    "gps_lat": 11.016842,
    "gps_lng": 76.955831
  },
  {
    "recorded_at": "2026-08-12T10:15:30.220Z",
    "lateral_g": 1.18,
    "speed_kmh": 89.1,
    "gps_lat": 11.016850,
    "gps_lng": 76.955840
  }
]
```

## 3. Status Codes & Error Handling

| Status Code | Meaning | Gateway Action |
| :--- | :--- | :--- |
| `201 Created` | Ingestion successful | Clear transmitted batch from local queue |
| `400 Bad Request` | Invalid payload JSON/schema | Log error, discard unparseable item |
| `401 Unauthorized` | Invalid/missing device token | Alert system administrator |
| `403 Forbidden` | Device not authorized for driver | Retain queue, retry when session re-assigned |
| `5xx / Network Error` | Backend offline / no signal | Retain queue, execute Exponential Backoff |

## 4. Exponential Backoff Retry Rules

1. Initial Retry Interval: 2 seconds
2. Multiplier: $2.0 \times (1 + \text{jitter})$
3. Maximum Retry Cap: 60 seconds
4. Queue Storage Limit: 10,000 readings (~8 minutes at 20Hz)
